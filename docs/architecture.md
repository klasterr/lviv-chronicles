# Архітектура

Огляд для того, хто хоче змінити або розширити гру. Короткий опис, запуск і керування — у [`../README.md`](../README.md).

public/photos/*  ─┤      (layout-avenue, layout-poi, frontage)      │
public/tex/*     ─┘                                                  ▼
                                      src/main.ts ─► Game (рендер, цикл, системи)
                                         ├─ buildCity      будівлі, дороги, колайдери
                                         ├─ addProps       проспект: дерева, лавки, фонтан, пам'ятник
                                         ├─ addAvenue      фото-фасади, McDonald's, вивіски, OSM-об'єкти
                                         ├─ Player         ходьба / політ / лавка / самокат

                                         ├─ Scooters       самокати Bolt

## 1. Системи координат і конвенції

Усе в метрах. Початок координат — центр bbox GeoJSON, проєкція рівнопрямокутна (на ~1 км похибка зневажна, див. `prepare-city.ts`).

| Вісь | Напрям |
|---|---|
| `x` | схід |
| `z` | **південь** (північ = −z) |
| `y` | вгору |

**Кути.** Є дві конвенції, їх не можна плутати:

* **Об'єкти (`rotation.y = yaw`):** локальна вісь +z іде у світі як `(sin yaw, cos yaw)`, локальна вісь +x як `(cos yaw, −sin yaw)`.
  Перетворення локальне → світ: `x = px + lx·cos + lz·sin`, `z = pz − lx·sin + lz·cos` (так у `Colliders.addRect`, `props.ts`, `grandpas.ts`). «Обличчя» об'єкта — локальне +z.
* **Камера / напрям руху (`a`, також кут самоката):** вперед = `(−sin a, −cos a)`, вправо = `(cos a, −sin a)`.
  Тому об'єкт, що дивиться вздовж камери з кутом `a`, має `yaw = a + π` (так садять гравця: `yaw: bench.yaw + π`; самокат: `setFromAxisAngle(up, a + π)`).

**Геометрія будівель.** Зовнішнє кільце має додатну площу в `(x, z)`, отвори (двори) — від'ємну; зовнішня нормаль стіни `n = (dz, −dx)/len`.
Висота: `lm.h` (орієнтири) → `height` OSM → `building:levels × 3,3 м` → за замовчуванням ~4 поверхи (малі будівлі до 80 м² — 3,5 м).

## 2. Конвеєр даних (`scripts/`, запускається вручну)

| Скрипт (`npm run …`) | Вхід | Вихід | Мережа |
|---|---|---|---|
| `prepare-data` (`prepare-city.ts`) | `export.geojson`, `data/osm-poi.json` | `public/city.json` | ні |
| `poi` (`fetch-poi.ts`) | bbox із GeoJSON → Overpass API | `data/osm-poi.json` | так |
| `photos` (`prepare-photos.ts`) | Wikimedia Commons (за `facade-config.ts`) | `public/photos/*.webp`, `src/world/avenue/facades.generated.ts`, `public/photos/CREDITS.txt` | так |
| `textures` (`fetch-textures.ts` + `optimize-textures.mjs`) | ambientCG | `public/tex/*.webp` (стиснуті до потрібних розмірів) | так |

Допоміжні модулі: `layout-avenue.ts` (розкладка проспекту), `layout-poi.ts` (вивіски та об'єкти з OSM), `frontage.ts` (стіна будинку, що дивиться на проспект),
`facade-config.ts` (кути фото-фасадів, висоти).

### `public/city.json`
Тип — `CityData` у `src/world/city.ts`.

* `spawn {x, z, yaw}` — на початку бульвару за фонтаном, обличчям до опери (камерний yaw).
* `buildings[]`: `id` (OSM), `r` (кільця: зовнішнє + отвори), `h` (висота; 0 = невідома), `lv`, `t` (тип), `sd` (рік `start_date`), `rs` (`roof:shape`), `bc` (`building:colour`).
* `roads[]`: `p` (полілінія), `k` (`highway`), `s` (`surface`), `w` (ширина; для проїжджої частини з `lanes × 3,1 м`).
* `street` (`Street`): `trees [x,z,seed,kind]`, `benches [x,z,yaw,kind]` (0 парковa, 1 довга, 2 дугова), `lamps`, `fountain`, `chess` (столики `[x,z,yaw]`),
  `drinking`, `beds`, `ribbons` (смуги граніту й газонів), `plaza`, `monument`; плюс `AvenueData` з `layout-poi.ts`: `fronts`, `signs`, `osm{benches,bins,bikes,lamps,hydrants,stops,trees}`, `crossings`, `bollards`, `laneMarks`.

### Розкладка проспекту (`layout-avenue.ts`)
Усі довжини й ширини беруться з GeoJSON, текстовий опис дає лише склад об'єктів і розміри окремих речей.

1. Вісь бульвару — середина між двома проїжджими частинами (`highway=primary` — захід, `secondary` — схід, ім'я «проспект Свободи»), заміряна по `z` від фасаду опери (найпівденніша точка контуру) до центру пішохідного майданчика `way/356593298` (пам'ятник Шевченку). Довжина секції ≈ 307 м.
2. Зони масштабуються на `довжина / 430`: площа Опери 0–85, північна частина 85–220, середня (шахи) 220–350, площа пам'ятника 350–430 (у метрах опису).
3. Поперечний переріз у частках чистої ширини (ширина між проїжджими частинами мінус їхні напівширини, 49–59 м): 4,5/27 — променада (на кожен бік), до 10/27 — газон.
4. Об'єкти: клени на краях площі, чотири ряди каштанів/лип (крок 7,5 м, «шахматка»), лавки (крок 15 м у північній частині, 11 м у середній), ліхтарі (18 м), шахова група (6 столиків, у східній смузі), питний фонтанчик, пам'ятник (за напрямом осі) і стела, два секторні газони, 12 дугових лав.

## 3. Рантайм (`src/`)

### Завантаження (`main.ts`)
Порядок: матеріали + `city.json` → `buildCity` → `addProps` → `addAvenue` → ґрунт → небо → `Player` → системи (`player`, `Sitting`, `Scooters`, `Grandpas`, `sky`, `props`, `avenue`) →
`compileAsync` + один кадр за екраном завантаження → екран «Натисніть, щоб почати». Стартовий екран знову показується при втраті захоплення курсора (`unlock`), крім моменту, коли відкрита шахова дошка.
`window.game` і `window.perfReport()` доступні в консолі для налагодження.
Адреси ресурсів (`city.json`, `tex/…`, `photos/…`) **без початкового `/`**, а в `vite.config.ts` `base: './'`: так збірка працює з підадреси (GitHub Pages) і з кореня домену.

### Цикл (`game.ts`)
`System { update(dt); preRender?(camera) }`. `Game.frame(dt)` викликає всі `update`, потім `preRender` (відсікання інстансів), потім рендер. Є адаптивний pixelRatio (1,5 → 0,65, якщо середній кадр > 21 мс; `?nogov` вимикає),
обробка втрати контексту WebGL, пауза в прихованій вкладці (`Timer.connect`).

### Місто (`city.ts`, `meshbuilder.ts`, `materials.ts`)
* Будівлі: стіни в секціях «цоколь / середні поверхи / верхній поверх» (стиль фасаду за `start_date`), вертексний колір штукатурки, дах окремим матеріалом. Геометрія накопичується у `Chunks` (чанк 400 м, індексовані буфери,
  нормалі Int8, кольори Uint8).
* Фасади: **один** матеріал на всі стіни — масив текстур (`DataArrayTexture`), шар вибирає атрибут вершини `tile`. Плитка 512 px (`FACADE_RES`) = 1 вікно × 1 поверх, намальована на canvas поверх фото штукатурки.
  Додати власну плитку: `extraFacadeTiles[ключ] = (g, S) => …` + `mats.facadeLayer(ключ)`.
* Дороги: стрічки, матеріал за (`surface`, шар), `polygonOffset` розв'язує накладання тротуарів/проїзду/граніту/газону (шари: проїзд 0, пішохідна 1, доріжки 2, граніт 6, газон 7, фонтан 8, парковки 9).
* Колайдери (`colliders.ts`): рівномірна сітка 20 м; відрізки стін з висотою, контури будівель (висота даху для посадки), малі перешкоди (`addBox`, `addRect`), лавки (`addBench` + `rayBench`).

### Орієнтири (`landmarks.ts`)
Таблиця `LANDMARKS` за OSM-id: перевизначення висоти/поверхів/кольору/стилю/даху або повна заміна геометрії (`skipMesh` + `model`).
Опера: фото-панель фасаду з альфа-каналом (небо вирізане) + купол. Вежа Ратуші (65 м): низ із каменю, середина — фото на чотирьох гранях, карниз, флагшток. Корпус Ратуші: жовтий, сірий дах.

### Проспект
* `props.ts` — об'єкти розкладки: смуги землі (граніт/газон), дерева (`kind` 0/1/2), лавки трьох видів, ліхтарі, шахові столики, питний фонтанчик, сухий фонтан (вріз у формі скрипки + 72 анімованих струменя), пам'ятник Шевченку, стела, газони з бордюром.
  Усе, що повторюється, — через `instanced()` → `CulledInstances`.
* `monument.ts` + `monument-layout.ts` — пам'ятник Шевченку (розкладка й колайдери — чиста логіка в `monument-layout.ts`, тест у `test-collide.ts`). Локальна система: +z — куди дивиться поет.
  Бронзова постать 4,45 м у довгому пальті з хутряним комірем, поясом і плащем за спиною, шапка, вуса, права рука біля грудей (поза — припущення, джерела її не описують), на гранітному п'єдесталі
  (3 сходинки: нижня на 10 см — лише візуальний «бордюр», дві інші суцільні; цоколь, темна шафа з табличкою «Т. Г. ШЕВЧЕНКО 1814 – 1861», карниз), поруч стела «Хвиля національного відродження»
  (дуга R = 9 м, 14 м, граніт 1 м + бронза 7,4 → 10,4 м хвилястим гребенем, зверху Оранта, разом 12 м) з рельєфами з обох боків, намальованими на canvas 512² (лицьовий — натовп, Перебендя, Сагайдачний; зворотний — жорна з датами XX ст., дерево з корінням, ґрати).
  Біля підніжжя — вінки, букети, лампадки на другій сходинці (всередині колайдера) і диск із кільцями гранітної інкрустації r ≤ 3,2 м (не заходить на газони r ≥ 3,5 м і на музиканта в 3,5 м).
  Бронза — вертексні кольори + `patina()` (верденіграй на верхніх гранях і потьоках), граніт — вертексні кольори; усе злито в 4 меші (бронза, камінь, стела з canvas, табличка з canvas), ≈ 4,3 тис. трикутників, без роботи на кадр.
  Колайдери: обертовий квадрат (половина 1,8 м, не вісьовий бокс), обидві грані й торці плити стели. Гравець підходить до сходинок упритул; музикант (3,5 м) і лавки (13 м), самокати (9 м) не зачеплені.
* `avenue/` — шар «реального світу»: фото-фасади (`facades.generated.ts`), McDonald's (`ground-front.ts`: логотип і вивіски намальовані на canvas), вивіски (`signs.ts`, атлас 1024²), мапні лавки/смітники/велостійки/зупинки/дерева, зебри, тумби.
* `instancing.ts` (`CulledInstances`): матриці інстансів зберігаються на CPU, перед рендером у `InstancedMesh` копіюються лише видимі (frustum, відстань, LOD). Ніколи не ставте `frustumCulled = false` вручну.

### Гравець (`player/player.ts`)
Станові режими: ходьба, політ, лавка, самокат. Механіка: гравітація 22 м/с², стрибок 7,5 м/с, ходьба 4 / біг 8 м/с, політ 14 / 45 м/с (стеля 300 м), радіус 0,35 м, висота очей 1,7 (сидячи 1,2, на самокаті 1,8 м).
Колізії лише по горизонталі й тільки зі стінами, вищими за рівень ніг, тому на дах можна приземлитись, а низькі лавки можна перестрибнути.

* **Сенсорне керування** (`device.ts`, `player/touch.ts`, `player/stick.ts`): `isTouch` = `pointer: coarse` або `?touch`. Pointer Lock на телефоні немає, тому гравець активний, коли `Player.active` = `controls.isLocked || touchActive`.
  `TouchControls` (плаваючий джойстик у лівих 40% екрана, огляд у решті) перетворює джойстик на клавіші через `Player.keyDown/keyUp` (`stickKeys`: 8 напрямків, Shift на краю), огляд — через `Player.look`,
  вертикаль у польоті — через `Player.climb`. Кнопки дій беруть зі списків `act` систем `Sitting`, `Scooters`, `Grandpas` (`Action { label, fire }`, тип у `device.ts`), тож нова контекстна дія — це запис у `act`.
  На телефоні вимкнені тіні (`?shadow` вмикає) і згладжування, стартовий pixelRatio 1, підказки з назвами клавіш приховані (їх замінюють кнопки), клік мишею в `Sitting` ігнорується (емульовані події не мають садити гравця).
  Екран паузи ігнорує клік у перші 400 мс після появи: торкання ☰ викликає ще й `click` на щойно показаному екрані.
* **Лавка** (`sitting.ts`): промінь погляду проти коробок лавок (`Colliders.rayBench`, до 4 м). `Player.sit()` плавно підводить камеру, `stand()` ставить гравця на 0,65 м перед лавкою. Підйом по події натискання клавіші, а не по опитуванню стану.
* **Самокат** (`scooters.ts`, `parking.ts`): `Player.mount()`/`dismount()`; `W` газ 3,5 м/с², `S` гальмо 7 м/с², накат 0,6 м/с², поворот 1,3 рад/с (пропорційно швидкості до 2,5 м/с), максимум **40 км/год** (`MAX_SPEED`).
  Самокати — один `InstancedMesh`; стани `parked → ridden → dropped → returning → parked`. Парковки — функція `parkingZones(street)` (тестується окремо).
* **Шахи** (`grandpas.ts`, `chess/`): два дідусі на лавках біля столиків 0 і 5. Опозиційну лавку визначає відстань 1,5–3,6 м до місця дідуся. Дошка (`chess/ui.ts`) вантажиться ліниво, пошук ходу — у Web Worker (`chess/worker.ts`).
  Рушій (`chess/engine.ts`): легкий — випадковий/жадібний; складний — негамакс alpha-beta, ітеративне поглиблення до 4 напівходів, тихий пошук, сортування MVV-LVA, ліміт 1,3 с. Інтерфейс масштабує клітинку під розмір вікна (`--s`).

### Вуличний музикант (`musician/`)
Гітарист за 3,5 м перед пам'ятником Шевченку (за напрямом `monument.yaw`, обличчям до пішохідної зони, між пам'ятником і лавками-дугою та парковкою самокатів), перед ним на землі відкритий кейс для гітари — скринька для чайових.
* `musician.ts` (`Musician`, система): фігура (злитий меш із вертексними кольорами) + окремий малий меш руки, що б'є по струнах, + меш кейса (темна оболонка, червоний плюш, піднята кришка) + один `InstancedMesh` монет (12 місць у кейсі).
  Далі 90 м усе приховано й не анімується. Колайдери: кейс (`addRect`) і сам музикант (`addBox`).
* Чайові: за ≤ 1,8 м від кейса з боку слухачів (`tip.ts`: `canTip`) — підказка «E — кинути чайові (10 ₴)» і запис у `act` (кнопка на телефоні). Монета летить дугою 0,45 с у наступне місце (`coinSlot`: після 12-ї перша зникає, лічильник `tips` росте далі),
  музикант киває й дякує випадковою реплікою в бульбашці (`bubble.ts`: `speechBubble(колір рамки, top)` → `say`/`tick`; ним можна замінити ручну бульбашку касира). Гаманця немає, сума фіксована.
* Хуки для звуку: `playing` (грає; керує анімацією руки), `onTip` (монету кинуто), `position` (де грає музика), `casePosition`, `tips`.
* Зона чайових (`TIP_R`) навмисно не перетинається із зоною посадки на самокат (2,5 м від самокатів на парковці за 9 м від пам'ятника): обидві дії висять на `E`.

### Аніматори в костюмах (`animators/`)
Троє людей у ростових костюмах — сірий Віслюк (довгі вуха, морда, грива), синій Сонік (голки назад, світла морда, червоні черевики з білим ремінцем) і Лабубу (хутро, високі заячі вуха, широка усмішка з рядом гострих зубів) — повільно (0,7 м/с) гуляють по центральній гранітній алеї бульвару.
* `route.ts` — чиста логіка (тест у `test-collide.ts` на даних `city.json`): петля-«стадіон» уздовж найдовшої смуги `granite` у `street.ribbons` — дві доріжки за 3,5 м по обидва боки від осі, на кінцях півкола, по 15 м від фонтана й площі пам'ятника (≈ 389 м). Від лав, дерев, ліхтарів, смітників понад 2 м; `Colliders.resolve` з радіусом 0,6 м уздовж усієї петлі нікого не зсуває.
* **Синхронно без мережі:** місце на петлі = `Date.now() / 1000 · SPEED` + зсув (троє рівномірно, ≈ 130 м один від одного), тож усі гравці бачать їх приблизно там само. Зупинка на обійми — лише локальна (`shortcut:` у коді): потім аніматор іде в 1,4 раза швидше, доки не наздожене спільний розклад.
* `costumes.ts`: кожен костюм — **один `SkinnedMesh`** (один виклик малювання, ≈ 4–5 тис. трикутників): злиті вертексні частини, кожна жорстко прив'язана до однієї з 5 кісток (тіло, руки, ноги). Ходьба: мах ніг і рук, підскок, перевалювання; поворот за напрямом петлі.
  Кістки додають одну шейдерну програму (skinning) і її варіант для тіні. Далі 80 м аніматор прихований.
* `animators.ts` (`Animators`, система): гравця виштовхує з кола 0,6 м («особистий простір», рух робить сам аніматор). Ближче 2 м і дивлячись на аніматора: `E` — обійняти, `H` — привітатися (`act`: дві кнопки на телефоні).
  `E` віддається іншим, якщо вони щось пропонують (`Items.aim`, самокат, музикант, кульки). Аніматор зупиняється, повертається до вас (на обійми ще й підходить до 1 м), обіймає (руки вперед і навколо, нахил, стискання, підскок) або тисне руку (права рука навхрест, кілька струшувань), каже репліку в бульбашці, за ~2,3 с іде далі. Погляд гравця м'яко повертається до нього. Звук — наявні рецепти `sit` / `stand`.

### Повітряні кульки (`balloons/`)
Дівчинка з в'язкою кульок на площі Опери: 8 м на захід від осі сухого фонтана й 6 м від його центру в бік південного краю (`fountain` у локальних координатах `(−8, 6)`; самокати — на східному боці), обличчям до точки старту.
* `seller.ts` (`BalloonGirl`, система): фігура `buildFigure` у масштабі 0,75 (дитина, кіска), піднята рука тримає в'язку з 8 кульок (один злитий меш, гойдається), колайдер `addBox`. Далі 90 м прихована.
  Ближче 2 м — підказка «E — купити кульку (50 ₴)» і запис у `act` (кнопка на телефоні); руки повні — «Руки зайняті». `buy()` кладе кульку випадкового кольору прямо в руки (`Items.give`, грає звук `onPickup`) і каже ціну в бульбашці. Гаманця немає.
* `balloon.ts`: `Balloon extends Item` (одна рука, геометрія на колір): нитка, вузлик, куля. Геометрія нахилена вперед (`TILT`), тож у руці кулька висить над рукою попереду й видна в кадрі, а не над камерою.
  `Q` на кульці — `Items.throwHeld` викликає `release()` замість кидка: кулька випрямляється, повільно піднімається з легким погойдуванням і за 6 с зменшується й зникає (`floatAway`, крок у `BalloonGirl.update`). `onThrow` не викликається: мережа розсилала б його як кидок, що розбивається.

### Входи в приміщення (`interiors/portal.ts`)
Спільний механізм для всіх приміщень (ресторан, магазини, опера): `Portal<R>` — двері на вулиці й кімната, що стоїть окремо на порожній землі за містом у власному **слоті**
(`x = bounds.maxX + 150 + slot · 150`, `z = bounds.maxZ + 150`; слот 0 — ресторан, 1–4 — магазини (`shops/`), 5–6 — резерв, 7 — опера). Підійти до дверей і дивитися на них — затемнення, `Player.teleport`, на час візиту `bounds` звужуються до кімнати;
такий самий вихід усередині (`spec.exit`). Кімната будується ліниво (`spec.build(origin)` при першому заході) і лишається в сцені схованою. `Portal.active` — приміщення, у якому гравець зараз (null надворі): за ним `audio/` вмикає «кімнатний» звук і кроки по плитці.
`portal.update()` викликає власна система приміщення щоразу; вона повертає `true`, коли гравець вільний діяти в кімнаті на першому поверсі (взаємодії — каса, полиці).

### McDonald's усередині (`restaurant/`)
Як в інтер'єрах старих GTA: кімната не вбудована в будівлю, а стоїть окремо на порожній землі за містом (`bounds.maxX + 150`, `bounds.maxZ + 150`, початок координат кімнати = її центр), вхід і вихід — телепорт із затемненням.
* `restaurant.ts` (`Restaurant`, система): дверна зона (0,9 м від намальованих дверей `FRONT35.mcd.door` + погляд на двері) → `go()` затемнює, `Player.teleport`, на час візиту `bounds` звужуються до кімнати
  (потім відновлюються). Кімната будується **ліниво** при першому візиті (`import('./interior')`), як і екран меню. Взаємодія за близькістю (каса, кіоски) → `act` (клавіша `E` і кнопка на телефоні), `menuOpen` — як `chessOpen`.
  Замовлення на касі видається одразу (рука касира + піднос з окремих предметів на прилавку + репліка), з кіоска — відкладається до «Забрати замовлення» на касі; попереднє невзяте замовлення прибирається. Піднос і їжа — предмети (див. «Предмети»).
* `layout.ts` (`L`): розміри кімнати та позиції каса / кіоски / піднос, локальні координати (+x схід, +z південь; гравець входить обличчям на північ). `interior.ts`: вся геометрія й колайдери,
  один злитий меш із вертексними кольорами + світні елементи (`MeshBasicMaterial`, у сцені немає додаткових джерел світла) + атлас 1024² (меню-борди, екран кіоска, логотип) + підлога; касир (`buildCashier`).
* `menu.ts` (меню, ціни умовні, `total`/`describe`/`units`/`pieces`, `MAX_UNITS`), `mc-items.ts` (їжа як предмети), `ui.ts` (`MenuUI`, DOM-оверлей меню, спільний для каси й кіосків).
* **Другий поверх.** `Colliders` вміє поверхи: `addFloor(x0,z0,x1,z1,hA,hB)` (висота лінійно по z — плита й пандус сходів), `groundAt(x, z, y)` віддає поверх, лише якщо він не вище за ноги більш ніж на 0,6 м
  (інакше під антресоллю гравця «підкидало» б нагору); стіни мають нижню межу (`addRect(..., h, lo)`: поручні другого поверху не заважають тим, хто внизу), лавки — власний рівень `y0` (`addBench(..., y0)`).
  Східці — суцільні блоки, фізично це пандус через їхні носики. Кабінки на лавках — звичайні `addBench`, тож на них сідають кліком.

### Опера (інтер'єр) (`opera/`)
Головний вхід Львівського театру опери та балету (арка посередині фото-фасаду) веде в окрему кімнату, слот 7 (`tone: 'hall'`), 44 × 64 м. Інтер'єр — **стилізована інтерпретація за описами**, а не план: факти й джерела в `avenue-research.md`.
* `world/landmarks.ts`: `operaFront(ring)` рахує перед (бік OBB, що дивиться на південь), панель фото і `door` — центральна арка на фото (470 з 1024 px по ширині, рівень землі); двері лежать у площині панелі, обличчям на вулицю.
* `opera.ts` (`Opera`, система; `Opera.make` у `main.ts`): `Portal` + білетер + програмки + «налаштування оркестру». `act` → кнопка на телефоні; `E` біля програмки бере її (`items.aim`), а не розмовляє.
* `layout.ts` (`OP`) — **чиста логіка без THREE**, тестується в `npm test`: розміри, `horseshoe(r, ds)` (шлях підкови: бічні прямі + пів-кола, з дотичною й нормаллю), `parterreSeats`/`tierSeats`/`seatGroups` (місця й лавки по 4–5 місць),
  `stairSteps`, `tierStrips` (кільце ярусу як тонкі прямокутники, бо `addFloor` — лише прямокутники) і `addOperaColliders` (усі стіни, поручні, сходи, меблі, лавки; використовується і в грі, і в тесті ходьбою).
* `interior.ts` (`buildHall`): один злитий меш із вертексними кольорами (≈ 34 тис. трикутників) + світний (лампи, вікна, люстри) + атлас-меш (плафон, завіса, розписи стелі фойє, дзеркала, вивіски, афіша) + мармурова підлога + `InstancedMesh` крісел; разом **8 draw calls, ≈ 62 тис. трикутників**.
  Текстури: атлас 1024² і мармур 512² (canvas, `atlas.ts`; ≈ 6,7 МБ з мипмапами). Усі матеріали з `polygonOffset` (−1…−3): підлога лише на 2 см над площиною землі міста, яка малюється пізніше й на відстані виграє тест глибини.
* **Вестибюль і фойє** (вхід на півдні, обличчям на північ): червона доріжка на мармурі, каси праворуч і ліворуч від дверей, гардероб із пальтами (ліворуч під галереєю), стіл білетера (праворуч), дві статуї муз, золоті пілястри, великі вікна й світловий ліхтар, три люстри.
  **Сходи**: два марші вздовж бічних стін (по 28 східців, 16 м, підйом 4,5 м; суцільні блоки + `addFloor`-пандус, як у ресторані), червона доріжка, балюстрада; внутрішній поручень — стіна (будь-якої висоти), верхня балюстрада `lo = 4,5`.
  **Верхнє фойє** («Дзеркальна зала», 4,5 м): галерея над північним кінцем, шість дзеркал, три розписи на стелі («Поезія», «Музика», «Хореографія»), проход у зал на двох рівнях (партер і ярус).
* **Зала** (підкова, за описом 4 яруси, 44 ложі, 1000 місць): бічні сторони прямі, ззаду півколо R = 14 м; партер — 13 дугових рядів по 5–45 місць (≈ 450), центральний прохід, кожні п'ять місць — лавка (`addBench`, клік — сісти; між рядами 1,5 м, щоб після вставання не застрягти);
  чотири яруси (4,5 / 7,9 / 11,3 / 14,7 м) з позолоченими парапетами, оксамитовим верхом, картушами й колонками; перший ярус — прохідний (кільце з прямокутних підлог, поручень `lo = 4,5`, кріселка по краю — теж лавки), решта — лише вигляд.
  Стеля з розписним плафоном (10 секторів, canvas), центральна люстра, багато глядачів-силуетів (голови над парапетами) — «повний зал» без 1000 мешів.
* **Сцена**: оркестрова яма — парапет 1,1 м із золотим поручнем і всередині пульти, стільці, подіум (яма на рівні партеру: площина землі міста сховала б занурену підлогу); у сцену заходити не можна (стіна по ямі й по рампі),
  але видно її: червона завіса (canvas) розсунута до країв, ламбрекен, золота рама просценіуму з гербом-щитом і двома ангелами, розписаний задник (градієнт), місяць, колони, сходи, трон, ялинки, софіти.
* **Білетер** (`usher.ts`, розширений підхід `buildCashier`): у фраку з червоною краваткою; ближче 3,4 м вітається (бульбашка `speechBubble`, піднімає руку), `E` ближче 2,8 м — нова репліка. Три програмки на столі — `Programme extends Item`.
* **Звук**: дверний дзвінок і кроки по плитці — від `Portal`/`audio/`; на вході в зал один раз за візит грає `tune` (рецепт у `sfx.ts`: оркестр налаштовується на ля, п'ять осциляторів, тихо). Інших змін у `audio/` немає.

### Предмети (`items/`)
Загальна система «взяти в руки й кинути»; їда з McDonald's — лише перший вид предметів.
* `item.ts`: `Item` — загальний предмет (меш з початком на основі, ім'я, сфера прицілу `radius`/`cy`, скільки рук потрібно, кольори уламків) і `Tray extends Item` — контейнер: вміст — діти меша підноса, `put`/`release`.
  Матеріали спільні: `worldMat` (світ) і `heldMat` (без `depthTest`, щоб предмет у руці не тонув у стіні, як viewmodel у шутерах).
  Нові види предметів — це підкласи, яким потрібні лише вигляд і назва: `McItem` (`restaurant/mc-items.ts`: бургер / картопля / напій / десерт за `Kind` меню, одна геометрія на вид) і `orderTray(cart)` (піднос 4 × 2, до `MAX_UNITS` = 8 штук).
* `items.ts` (`Items`, система після `Player`): приціл променем по сферах у межах 3 м, `E` бере предмет, `T` — весь піднос (піднос займає дві руки, окремий предмет — одну; рук дві), `Q` кидає останнє взяте.
  Кинутий предмет летить балістично (10 м/с + підкидання, гравітація 14), перевіряється зі стінами (`Colliders.resolve`) і землею (`groundAt(x, z, y)`, тож на другому поверсі приземляється на плиту) і **розбивається та зникає**: 16 уламків з `InstancedMesh` (пул 60), кольори беруться з предмета (піднос додає кольори вмісту).
  `add(item, x, y, z)` кладе предмет у світ, `remove(item)` прибирає без ефекту (замінене замовлення). Хуки `onPickup` / `onThrow` / `onBreak` `(item, позиція)` — для звуку й чого завгодно ще.
  Їжа й напої: `ItemOpts.edible` (`'eat'` | `'drink'`; `McItem` за видом меню, `ShopItem` — таблиця `EDIBLE` у `shops/goods.ts`). `X` бере останнє їстівне з рук або з підноса в руках, несе до рота й за 1,4 с з'їдає за три укуси (зменшується) чи випиває за три ковтки (нахиляється); хук `onBite` — звук.
  `hitTest(точка, item)` питають для кожного летючого предмета вздовж відрізка кадру кроком 15 см (щоб на повільному кадрі не проскочити тіло); `true` — предмет розбивається там. Його задає `net/`.
  Кнопки для телефону — у `act` (`Взяти: …`, `Взяти весь піднос`, `Кинути: …`). `Items.aim` читає `Restaurant`: `E` біля підноса бере предмет, а не відкриває меню каси.

### Звук (`audio/`)
Усе синтезується на льоту через Web Audio, без жодного файлу; `?nosound` вимикає повністю (система не додається), `M` — вимкнути/увімкнути (тост «Звук вимкнено (M)»).
* `logic.ts` — чиста логіка без DOM/AudioContext (тестується в `npm test`): `distGain` (повна гучність до 2 м, квадратичне згасання до `range`), `panFor` (пан із yaw камери: праворуч = `(cos a, −sin a)`), `stride`/`stepVol` (кроки за пройденою відстанню),
  `itemClass` (піднос / стаканчик / їжа), `fingerpick` + `schedule` (патерн гітари й look-ahead планувальник) і `pluck` (Karplus-Strong).
* `sfx.ts` — `sfx` (singleton): `unlock()` створює `AudioContext` лише в жесті користувача (клік по стартовому екрану, торкання, подія `lock`), до того звуку й попереджень немає. Майстер → `DynamicsCompressor` (м'який лімітер).
  `sfx.play('назва', pos?, vol?)`: без `pos` звук «в голові», з `pos` — відстань + `StereoPannerNode` від камери (`sfx.cam`), без PannerNode/HRTF. Рецепти — таблиця `R` (осцилятор із ковзанням висоти + фільтрований шум зі спільного буфера 4 с).
  Стеля — 48 одночасних джерел (`sfx.live`), зайві відкидаються. `sfx.sync(run)` призупиняє контекст у прихованій вкладці й на екрані паузи (`#overlay`).
* `beds.ts` — `Beds`: постійні звуки, граф будується один раз, на кадр лише присвоєння `.value` (без алокацій): фон міста (низький шум), гул ресторану, фонтан (за відстанню до 40 м, з паном), гул самоката (висота й гучність від `Player.speedMs`) + шум шин, вітер у польоті (від швидкості).
  `Music` — гітарист: Am F C G | Am Dm E Am, арпеджіо вісімками 92 уд/хв, ноти — Karplus-Strong буфери, кешовані за висотою; планувальник додає ноти на 0,3 с наперед за годинником контексту, чутно лише в межах 35 м (далі нічого не планується).
* `system.ts` — `AudioSystem` (у `game.systems` останнім): з публічного стану `Player` (позиція, `vspeed`, `seated`, `riding`, `flying`, `speedMs`) виводить кроки (плитка всередині — за `Restaurant.inside`), стрибок, приземлення, посадку/підйом, защіпку самоката;
  вішає `Items.onPickup/onThrow/onBreak` і `Musician.onTip` (дзенькіт монети в позиції кейса). Прямі виклики `sfx.play` лише там, де стан не видно: дверний дзвінок і дзвінок видачі (`restaurant.ts`), кліки меню (`restaurant/ui.ts`), хід у шахах (`chess/ui.ts`).
* Нова реакція — рецепт у `R` і виклик `sfx.play`; новий постійний звук — гілка в `Beds`. Рівні й тембри підібрані без прослуховування (перевірено лише відсутність помилок і ненульовий сигнал без кліпінгу), тож їх варто підкрутити на слух.

### Мультиплеєр (`net/`)
Без сервера: браузери в одній кімнаті з'єднуються напряму через WebRTC (`trystero`, сигналізація через публічні Nostr-реле). Модуль імпортується динамічно після старту (`main.ts`), `?solo` вимикає його, `?room=` задає кімнату.
* `sync.ts` — чиста логіка (тестується в `scripts/test-net.ts`): правило «новіший запис перемагає» для самокатів і перевірка **кожного** вхідного повідомлення (числа скінченні й у межах, індекси в діапазоні, id предметів за шаблоном, ім'я ≤ 16 символів). Будь-який пір може надіслати що завгодно, тож неправильне повідомлення просто відкидається.
* `net.ts` — `Net` (система в `game.systems`): дії `pose` (10 Гц), `hello` (ім'я), `scoot`, `snap` (знімок для новачка), `gone`, `throw`. Спільний стан без арбітра, тому кожне правило сходиться само:
  самокат — LWW-регістр на годиннику Лемпорта (`t`, при рівності менший id автора); їздити можна лише «від себе»; якщо твою поїздку перебили паркуванням, вона заявляється наново; якщо гравець пішов, його самокат записує як покинутий пір з найменшим id.
  Узяті спільні предмети — множина id, що лише росте (`Items.gone`; id мають товари на полицях `shop:<slot>:<i>` і програмки `prog:<i>`). Лавки — перевірка `Sitting.taken`; при одночасному сіданні встає гравець із більшим id.
  `Items.onPickup/onThrow` уже зайняті звуком, тому `Net` додається в ланцюжок після `AudioSystem`.
  Влучання: кожен клієнт сам симулює кожен кидок (`throw` несе позицію, швидкість, кольори й назву) і через `Items.hitTest` перевіряє тіла, які бачить. Свій кидок у чужу фігуру — фігура відхиляється (`Avatars.hitAt`), напис «Влучання: …».
  Чужий кидок у тебе (рахує твоя справжня позиція, окремого повідомлення немає) — `Player.hitBy` (поштовх, підскок, смикання й тремтіння огляду), звук `hit`, червоні краї екрана, `navigator.vibrate`, напис, хто й чим кинув.
* `avatars.ts` — фігури інших гравців (`interiors/figure.ts`), колір за хешем id, ім'я — спрайт із canvas (тексту як HTML немає), плавний рух до останньої пози; група з `userData.keep`, тож гравців видно й у приміщеннях (кімнати — звичайні світові координати).

### Небо й тіні (`sky.ts`)
Градієнтна сфера, туман 120–600 м, hemisphere + directional світло, одна карта тіней 2048² навколо гравця (±70 м), центр прив'язаний кроком 8,75 м і перемальовується лише при зміні кроку.

## 4. Перевірка

| Команда | Що перевіряє |
|---|---|
| `npx tsc --noEmit` / `npm run build` | типи (strict), збірка (`three` окремим чанком, чанки `ui` і `worker` для шахів завантажуються лише при першій партії) |
| `npm test` | `scripts/test-collide.ts`: колізії, дахи й двори, поверхи/пандус/поручні, вибір лавки променем, арифметика меню, розкладка парковок, магазини (осі, двері, вивіски, кошик), джойстик → клавіші, звук (крива відстані, пан, кроки, патерн і планувальник гітари); `scripts/test-chess.ts`: мат в один хід, безкоштовний ферзь, пат, обидва рівні, складний не програє легкому; `scripts/test-net.ts`: злиття стану самокатів не залежить від порядку, перевірка мережевих повідомлень |
| `npm run perf` | `scripts/perf.mjs` + `scripts/perf-budget.json`: draw calls, трикутники, програми, пам'ять текстур, розміри; детально в [`performance.md`](performance.md) |

Візуальна перевірка: headless Chrome через `puppeteer-core` (SwiftShader, ~3–6 fps, тому FPS не вимірюється). Камеру задають у консолі:
`game.camera.position.set(x, y, z); game.camera.rotation.set(pitch, yaw, 0, 'YXZ')`. Для тестів захоплення курсора вмикають вручну: `game.systems[0].controls.isLocked = true`.
Зручні точки огляду: `VIEWS` у `src/perf.ts`.

### Стан перевірок (останній запуск)
* `tsc`, `npm test`, `npm run build`: проходять.
* `npm run perf`: **десять бюджетів перевищені** (після додавання предметів, звуку, музиканта, магазинів, опери й нового пам'ятника), решта в нормі. Бюджети свідомо не піднімали.
  * `draws.spawn` 51 (50), `draws.townhall` 57 (55), `draws.aerial` 64 (60), `draws.plaza` 60 (55), `meshes` 94 (90), `programs` 25 (24), `textures` 29 (28) — разом +1…+5 на вигляд: фасади магазинів (3 виклики), музикант (4), пам'ятник (стела й табличка з canvas);
  * `texMB` — 85,9 при 75 (було 78,5): фото-фасади й опера (фото опери 2048×1565 ≈ 17 МБ), canvas-текстури пам'ятника й фасадів магазинів; `size.texKB` — 1686 (1400);
  * `size.jsGzipKB` — 246 при 180: у суму входять ліниві чанки (шахи, ресторан, магазини, опера, меню, звук ≈ 60 КБ gzip), які на старті не вантажаться; початковий JS ≈ 200 КБ gzip.
  Варіанти: стиснути фото опери й атлас фасадів, злити canvas-текстури фасадів і пам'ятника в один атлас або прийняти нові значення.
* Усередині будь-якого приміщення (`Portal`) світ надворі ховається (`visible = false`; `userData.keep` — небо, предмети), тож кадр там коштує 5–19 draw calls і 4–43 тис. трикутників (до цього місто малювалося повністю: ~157 викликів, ~1,7 млн трикутників).
* FPS на реальному залізі не вимірювався.

## 5. Як розширювати

* **Нова система з тиканням** (NPC, час доби): клас із `update(dt)` → `game.systems.push(...)` у `main.ts`. Потрібен вигляд на кадр — `preRender(camera)`.
* **Новий повторюваний об'єкт:** `instanced(geo, mat, items, place, cast, { maxDist, lods })` у `props.ts`; для понад ~100 трикутників додайте дешевший LOD. Не додавайте нові матеріали на чанк — це нові draw calls.
* **Новий орієнтир:** запис у `LANDMARKS` за OSM-id (`h`, `floors`, `tint`, `style`, `roof`, `skipMesh`, `model`).
* **Фасад із фото:** додайте рядок у `scripts/facade-config.ts` (чотири кути в пікселях мініатюри 1920 px, висоти) і запустіть `npm run photos`; ширина панелі береться з GeoJSON, а не з фото.
* **Нова лавка / тип лавки:** зареєструйте через `colliders.addBench(x, z, yaw, hw, hd, h)` — вона стане клікабельною.
* **Новий дідусь / рівень:** запис у `GRANDPAS` (`grandpas.ts`: стіл, вигляд, ім'я, репліки) і, за потреби, новий `Level` у `chess/engine.ts`.
* **Нова парковка самокатів:** функція `zone(...)` у `parking.ts` та запис у `parkingZones`.
* **Нова вулиця за тим самим методом:** узагальнити `layout-avenue.ts` (зараз прив'язаний до двох ліній проспекту) — вісь, ширина й зони рахуються з геометрії.

## 6. Ідеї та відомі прогалини

* 3D-фігури на шаховому столику (зараз партія видна лише в накладці), промоція не на ферзя, відміна ходу, вибір кольору.
* Самокат: обхід перешкод при поверненні, колізії самокатів між собою, акумулятор/тариф.
* Нічне освітлення (ліхтарі вже мають світні лампи), трамвайні дроти, `roof:shape`, тераса McDonald's, відвідувачі й кухарі в McDonald's; звук без справжніх семплів (усе синтезоване, може звучати «електронно»).
* Свіжіші фронтальні фото для №27, №29 й опери; KTX2 для текстур (потрібен `toktx`/`basisu`).
* Телефон: аналоговий джойстик (зараз цифровий), вибір лавки/самокат торканням по об'єкту, повноекранний режим на iPhone (PWA-маніфест), перевірка на реальних пристроях.
